## Повторение программной проверки

Диагностика хранится в tools, вне production addon. Временно скопируйте:

- `tools/ME_CSH_Audit.c` → `ME_Conflict_Spawn_Helpers/Scripts/WorkbenchGame/WorldEditor/ME_CSH_Audit.c`.
- `tools/ME_CSH_AuditGame.c` → `ME_Conflict_Spawn_Helpers/Scripts/Game/ME_Conflict_Spawn_Helpers/ZZ_CSH_AuditGame.c`.

Имя ZZ обязательно: modded-диагностика должна загружаться после основного расширения класса. Откройте отдельную тестовую сессию addon.gproj и проверьте компиляцию. Через уже настроенный локальный Workbench NET API вызовите handler `ME_CSH_Audit` сначала с `action: open`, дождитесь загрузки, затем с `action: audit`. Первый вызов открывает тестовый мир; не используйте его поверх несохранённой пользовательской сцены. Второй временно создаёт/удаляет тестовые сущности и возвращает счётчики.

После проверки удалите только две временные копии из Scripts, оставив исходники в tools, и заново проверьте компиляцию чистого аддона. Эти диагностические файлы нельзя включать в публикацию.
